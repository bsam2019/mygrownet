# ADR-011: Shared App Shell via Inertia Visit

**Status:** Accepted  
**Date:** 2026-07-26  
**Author:** Platform Core Team

## Context

The platform has multiple independently-deployed applications (BMS, StockFlow, GrowFinance, BizBoost, BizDocs) that users interact with as a unified system. When a user navigates from BMS to StockFlow, they should feel like they switched departments — not like they left one application for another.

**Requirements:**
- Each app must remain independently deployable (separate builds, separate servers)
- Navigation between apps must feel seamless (no full-page redirects with flicker)
- The shell (sidebar, topbar, user menu, theme) must be consistent across apps
- Each app controls its own navigation items
- No build coupling between apps (no shared webpack/vite config)

**Four patterns were evaluated:**

| Pattern | Description |
|---|---|
| Full redirect (app shelf) | Each app on its own subdomain. Navigation = full browser redirect. |
| iframe with JS bridge | Mother app loads target app in iframe. JS bridge handles auth, nav, theming. |
| **Shared shell via Inertia visit** (chosen) | Each app imports the same shell component from a shared package. Navigation uses Inertia's built-in visit mechanism to replace the content area. |
| Micro-frontend (module federation) | Single SPA shell loads federated modules from each app's build output. |

## Decision

Adopt **Pattern 3.5: Shared App Shell via Inertia Visit**.

All apps import a shared `PlatformShell` Vue component from a `@mygrownet/platform-shell` package (or from `resources/js/components/` in Platform Core). The shell is identical across apps, but each app supplies its own navigation items as a prop. When the user clicks a link, Inertia visits the new URL and replaces only the content area — the shell stays in place.

### Architecture

```
Each app's root layout (e.g., BMSLayout.vue):

<template>
    <PlatformShell :nav-items="bmsNavItems">
        <slot />  ← Inertia page content renders here
    </PlatformShell>
</template>
```

```
Each app's entry point (e.g., app-bms.ts):

import PlatformShell from '@/components/Platform/PlatformShell.vue'
// or: import { PlatformShell } from '@mygrownet/platform-shell'

app.component('PlatformShell', PlatformShell)
```

```
User clicks "Inventory" in BMS sidebar
    → Inertia.visit('https://stockflow.apps.mygrownet.com/inventory')
    → Inertia fetches StockFlow page
    → StockFlow page includes PlatformShell
    → PlatformShell renders with StockFlow nav items
    → Browser URL updates to stockflow.*
    → User sees consistent sidebar with different nav items
```

### Shell responsibilities

The `PlatformShell` component owns:
- Sidebar container (collapsible, responsive)
- Site header / topbar
- Theme toggle (dark/light mode)
- User dropdown (profile, logout)
- App switcher (navigate between applications)
- Context switcher (switch organization)
- Command palette (Ctrl+K)
- Navigation progress indicator
- Mobile drawer behavior

Each app provides:
- Navigation items (icon + label + route + active detection)
- Page content (via default slot)

### Cross-app navigation

When a user clicks a link to another app, Inertia handles it as a standard visit. The shell component is the same, so Vue reuses the existing DOM nodes where possible:

```
/* Sidebar link to another app */
<a :href="route('stockflow.dashboard')" @click.prevent="router.visit(href)">
    Inventory
</a>
```

Inertia preserves the shell because it's the same component. Only the page content and URL change. The shell reads context from `usePage().props.workspace` which is updated on each visit.

## Alternatives Considered

| Option | Pros | Cons |
|--------|------|------|
| **Full redirect** | Simplest to implement. True independent deployability. No coupling. | Full page reload on every app switch. Browser history is messy. Tab proliferation. Lose Inertia's instant navigation. |
| **iframe with JS bridge** | Apps are fully independent. Bridge handles auth/nav. No build coupling. | iframe scroll issues. Slower initial load. Bridge complexity. SEO issues. Accessibility challenges. |
| **Shared shell (chosen)** | Feels like a single app. Inertia visit is fast. No iframe issues. Each app independently deployable. | Requires shared npm package. Version skew if shell updates and one app doesn't. |
| **Micro-frontend** | Seamless UX. True composition at runtime. | All apps must share Vue version. Build pipeline complexity. One app's deploy can break the shell. Framework lock-in. |

## Consequences

**Positive:**
- Navigation between apps feels instant — no full-page reloads
- Consistent UI chrome across all apps without coupling
- Each app retains independent deployability (separate build, separate server)
- Works with existing Inertia infrastructure (no new transport layer)
- Each app controls its own nav items and page content

**Negative:**
- Requires a shared `@mygrownet/platform-shell` package that all apps import
- Version skew risk: if the shell updates, each app must bump its dependency
- Apps must agree on the shell interface (props, slots, events)

**Trade-off:**
- The shell is a compile-time dependency, not a runtime composition. Updating the shell requires rebuilding each app. This is acceptable because the shell changes infrequently (styling tweaks, new chrome features) and a coordinated rebuild is trivial with CI.

## Implementation

### Component interface

```typescript
interface PlatformShellProps {
    navItems: NavItem[];
    showAppSwitcher?: boolean;  // default true
}

interface NavItem {
    label: string;
    href: string;
    icon: Component;
    active?: boolean;       // override auto-detection
    badge?: string | number;  // optional notification badge
    external?: boolean;       // opens in new tab
}
```

### Files

- `resources/js/components/Platform/PlatformShell.vue` — the shell component
- `resources/js/components/Platform/AppSwitcher.vue` — app switcher dropdown
- `resources/js/composables/useShell.ts` — shared composables (theme, collapse, context)
- Existing `WorkspaceLayout.vue` refactored to wrap `PlatformShell`

### Migration

Each app's custom layout (e.g., `StockFlowLayout.vue`, `GrowFinanceLayout.vue`) currently renders its own sidebar. These will be refactored to import `PlatformShell` and pass their nav items as a prop. The layouts become thin wrappers:

```vue
<script setup lang="ts">
import { PlatformShell } from '@/components/Platform/PlatformShell.vue';
import { navItems } from './stockflow-nav';
</script>

<template>
    <PlatformShell :nav-items="navItems">
        <slot />
    </PlatformShell>
</template>
```
